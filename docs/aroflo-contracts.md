# AroFlo HMAC area allowlist

This is a deliberately narrow legacy-HMAC contract, curated solely from the supplied official Postman collection’s embedded legacy reference, its formal per-zone WHERE/JOIN/ORDER tables, and its dedicated request scripts. Sources retrieved on 2026-09-10: [legacy API base/reference](https://api.aroflo.com/) and [official AroFlo Postman collection](https://www.postman.com/aroflo/workspace/aroflo-api/collection/d73f2bdb-5f73-4498-b88c-32bf44367b8e). No response payload has been used to infer a writable field.

The source’s formal tables are unioned with dedicated official scripts. `fields` in the code and public fixture contain only public identifiers, formal filter/order fields, and explicit scalar XML leaf paths. Archive, delete, and link-processing mutations are not exposed. Field metadata records the source type plus documented creation requirement, mutability, and sensitivity where applicable.

## Curation rulings and source discrepancies

- Locations and Quotes are read-only. Schedules are create-only. Invoices are update-only through the explicit official invoice contract and remain subject to the separate financial-write gate.
- The dedicated `Create Schedule` script serializes a `<schedules>` payload but incorrectly builds `zone=clients`; formal schedule documentation and all schedule reads use `zone=schedules`, so the contract uses `schedules`.
- The formal client table does not permit a `notes` JOIN. The collection folder labelled `JOIN notes` actually sends `join=locations`, so no unsupported Clients `notes` JOIN is allowed.
- The task scripts use both `material`/`materials` and `notes`/`tasknotes`; both are preserved as distinct official script spellings.
- `linkprocessed` remains a read filter where official scripts use it; no link-processing mutation is exposed.
